# Domain Docs

This repo has a single context.

## Before exploring, read these

- **`CONTEXT.md`** at the repo root, the glossary.
- **`README.md`**: the section of the area you are about to work in, which says
  why each pick was made.

## Use the glossary's vocabulary

When your output names a domain concept (in an issue title, a refactor proposal,
a hypothesis, a test name), use the term as defined in `CONTEXT.md`. Don't drift
to synonyms the glossary explicitly avoids.

If the concept you need isn't in the glossary yet, either you're inventing
language the project doesn't use (reconsider) or there's a real gap (note it for
`/domain-modeling`).

## Flag conflicts with a stated choice

If your output goes against a choice the README explains, say so explicitly
rather than silently overriding it. Every pick can change, as long as the change
is deliberate.
